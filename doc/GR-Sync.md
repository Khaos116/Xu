## 代码关系

XU 的任务层更接近 GR，适合以 GR 为主要移植来源，AG 用于核对接口与边界处理。

迁移前按各自业务包目录统计 Java/Kotlin 源文件：XU 216/10，GR 234/3，AG 1/320。
XU 与 GR 有 207 个相同相对路径源码文件，其中 135 个替换包名、忽略空白后完全相同。
这只是源码关系指标，不代表功能覆盖率。AG 的任务目录、模块拆分和 Kotlin 实现差异明显，不能整目录覆盖。

迁移时一并修正 GR 鱼塘中发现的缺陷：

- 兑换成功也写入当天失败标记。
- 钓鱼循环末尾无条件清零失败计数，导致连续失败上限失效。
- 自动黑名单开关没有被加入黑名单的逻辑使用。
- 状态查询与广告处理互相调用可能反复重入；查询失败仍可能沿用旧钓竿数量。
- 任务等待忽略线程中断；补充中断及账号切换后的请求拦截。
- 浏览循环次数使用 `max`，改为最多 10 次；完成请求与令牌使用 JSON 构造，避免引号、反斜杠破坏参数。

## SO 的作用与移除范围

XU 与 GR 的 arm64 `libsesame.so` 都是 1,378,744 字节，SHA-256 均为
`5da46bb90e2e599ac4cb59e397cc52e98f542f4812873db8ade4e2e6d4b16049`。

二进制导出符号和字符串可确认，它包含 JNI 初始化、庄园任务/抽抽乐任务、任务状态检查、AES 加解密及 unlockSesame 入口，并引用旧包名和 Alpha 扩展。这不是 Android 或 Xposed 必需的运行库。仅凭导出符号不能断言其中每个分支的实际行为；本次没有执行或完整反编译该二进制。

当前 XU 的庄园普通任务和抽抽乐主流程已经使用 Java RPC；LibraryUtil 的 native 任务方法没有有效业务调用，但 ApplicationHook 仍在支付宝 Service 创建时强制加载 SO。
GR 已注释这一加载，并用 Java 实现庄园任务；其仓库仍保留 SO，旧配置 UI 也仍尝试加载，所以 GR 本身并非完全无 SO。

本次已删除四个架构的 `libsesame.so`、旧包名 LibraryUtil 桥接类、强制加载及专门拦截 native 提示的 Toast Hook。
水印改为原来的 Java 回退值，删除未接入构建的 watermark C++/CMake 文件。仅移除项目自带且已替代的原生库，不排除第三方依赖所需的原生库。

## 保留与限制

- 保留 XU 的 Miuix 界面、三个渠道、签名、Legacy APK 归档和已完成的 GMT+8 处理。
- GR 的版本伪装、强制关闭任务、小鸡禁止睡觉、历史错误永久记忆等属于具体版本/个人偏好，不直接覆盖 XU；它们不等同于新增可用任务。
- GR 家庭 Kotlin 实现中的部分开关键与其配置列表不一致。本次只移入可接通的增强，不整体替换 XU 家庭实现。
- 鱼塘令牌由当前账号配置提供；不读取可能混有其他账号的旧抓包日志。令牌缺失/格式不正确时跳过钓鱼，任务领奖仍可单独配置。
- GR 的 `openMiniProgram` 仅有日志，是占位实现；不能据此宣称完成了真实广告页面浏览。接口接受与否仍以服务端为准。
- 不恢复缺少可审查源码的 SO 内 Alpha 能力；也不声称移除了所有 Android 依赖中的 SO。
- 本次不触发真实支付宝任务、分享、兑换或 AI 联网请求。编译、离线检查不能证明服务端各项功能当前都可用。

## 验证

`scripts/check_gr_sync.py` 编译实际任务源码，在内存 RPC/持久化边界下验证任务筛选、鱼塘开关/时区/成功判定/令牌/黑名单/切号与取消、家庭兑换参数与防重复。
`scripts/check_gemini.py` 验证普通/联网搜索请求结构和错误路径。
`scripts/check_gmt8.py` 继续验证四个宿主默认时区下的业务时间及日状态。
最终验证均通过：Normal/Compatible Java 与 Kotlin 编译、Legacy Release 打包与 lintVital、归档哈希、APK 原生库清单、v2 签名校验。
模拟器覆盖安装与冷启动正常；“其他”配置显示鱼塘及 Gemini 联网搜索，鱼塘默认间隔正确显示 60 分钟。

产物：`APK/Release/Sure-Xu-Legacy-1.3.0_20260912_132049.apk`。
APK 中不含 `libsesame.so`、`libwatermark.so` 或旧 LibraryUtil 桥接类；仍保留 AndroidX 图形路径依赖的 `libandroidx.graphics.path.so`。
